# CODING-STANDARDS.md（首版，W14 retro 收编）

> 判断性取舍沉淀：每条来自真实评审/审计争议，不是风格偏好。
> 配套机械守卫：scripts/pre-commit-guard.sh（确定性检查清单已脚本化）。

## 1. 契约分层：数值契约与结构契约必须分离

**取舍**：换核演练证明——金标断言（数值）与排序/状态/隔离断言（结构）分层后，
换实现只需重冻结数值层。混层的测试套件在换核时整批失效。
**规范**：测试文件头部用注释块声明黄金期望来源（E4 独立直算）；数值断言集中
命名常量（SIM_GOLDEN/TAIL…），结构断言不引用数值常量。

## 2. 跨包测试即集成测试

**取舍**：labels 独立 venv 演练实锤——import reco_io 的「单包测试」在独立安装时
ImportError。ADR-0001「包独立可测」与测试便利性冲突时，独立性赢。
**规范**：import 其他 reco 包的测试一律放根 tests/（或显式标注集成票）；
单包测试只 import 本包模块。共享 fixture（如 perf 打点助手）自持最小复刻，
不跨包借。

## 3. 守卫必须纯函数

**取舍**：W8 score 语义守卫初版用 config.pop「消费即移除」——副作用让纯函数
契约失守（同输入不同输出，调用方 config 被改写）。纯函数是 rank 唯一入口
逐位一致性的根基。
**规范**：模块级接缝（score/feedback/profile）内任何被测函数不得改写入参；
需要「防篡改」用调用后对比断言，不用就地修改。

## 4. 余弦类度量的测试夹具必须二维+

**取舍**：单维向量全部同向（余弦恒 1）——S1 夹具三轮失败同根因；W14 换核
后同类问题在欧氏核下不复现（度量无关的教训：先证夹具可分辨再断言序）。
**规范**：涉及相似度排序的夹具至少两个维度，且不同候选间 sim 值互异；
测试注释里写明各候选的期望 sim 推导。

## 5. 机制选型先做不变量快检

**取舍**：W10「正交分量混合」机制性无效（余弦对整向量缩放不变）——落实现前
一个 30 秒的数学快检就能拦住。机制=「通过现有契约通道表达」，先证明通道
数学上可达目标，再写代码。
**规范**：任何「把 X 混入 Y 以达成 Z」的机制设计，先手算一个反例/正例
（黄金值冻结工序），证明 Z 可达且不破坏其他契约。

## 6. 显式状态优于隐式全局

**取舍**：rank._last_status 是审计点名的 low 遗留（进程内状态、多线程不安全）；
但当时的替代方案（异常携带状态）会让 no_candidates 这种正常路径抛异常。
**规范**：入口函数的「状态披露」随数据走（返回值字段），不用模块级可变全局；
确需全局（如缓存）必须线程安全并入审计清单。

## 7. 依赖声明=架构 L98 表格的机械镜像

**取舍**：cli/ui pyproject 漏声明 reco-store（可跑通全仓但不独立可装）——
演练才暴露。pyproject 是依赖方向的唯一机器可读载体。
**规范**：改任何 import 结构时同步 pyproject dependencies；验收清单固定
含「7 包独立安装」项（v7 脚本已入库可重放）。

## 8. PR-first 的 add 清单=触碰文件全集

**取舍**：W10 首提交漏 add score.py 接缝扩展（跨文件改动），靠 git status
自查兜住。触碰面>声明的提交会让评审者看到假 diff。
**规范**：提交前 git status 对照本票 changedPaths 声明——多出的文件要么补
披露要么撤出；跨文件接缝改动单独成 commit（b5cfa96 先例）。
